# Процедура предоставления экземпляра экспертам

## Вариант A — изолированный демонстрационный контур

1. Зафиксировать release SHA, image digests и контрольные суммы.
2. Развернуть отдельный контур без production-данных, используя синтетический набор проектов и документов.
3. Создать персональные временные учётные записи экспертов с минимально достаточной ролью.
4. Передать URL, логин и одноразовый канал получения пароля; секреты не включать в заявление или публичную документацию.
5. Предоставить сценарий проверки: вход → проект → документы → договор → задачи/риски → аудит → OCR → отключение внешнего AI.
6. Включить журналирование входов и изменений без записи текста секретов и документов в технические логи.
7. Установить срок доступа `[ДАТА/СРОК]`, контакт поддержки и порядок продления.
8. После завершения отозвать учётные записи и сохранить протокол предоставления доступа.

## Вариант B — комплект для локального развёртывания

Передать подписанный manifest, исходный/исполняемый комплект согласно решению владельца, `.env.example`, публичную инструкцию, SBOM, license texts, синтетические fixtures и checksum. Эксперт задаёт собственные секреты. Никакие production credentials или клиентские документы не передаются.

## Контрольный лист экземпляра

- `[ ]` наименование и версия совпадают с заявлением;
- `[ ]` SHA и checksum совпадают с досье;
- `[ ]` установка воспроизводима независимым специалистом;
- `[ ]` функции доступны без аккаунта разработчика, кроме явно заявленных внешних интеграций;
- `[ ]` режим без внешнего AI проверен сетевым контролем;
- `[ ]` синтетические данные не содержат персональных/клиентских сведений;
- `[ ]` назначены технический и юридический контакты.

Ответственный: `[ФИО, должность, контакты — предоставляет правообладатель]`.
