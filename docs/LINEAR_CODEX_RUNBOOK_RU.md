# Linear → Codex → GitHub: рабочий контур

Этот контур делает связь изменения с одной задачей Linear проверяемой в репозитории. Он не хранит токены, не обращается к Linear API и не закрывает задачи автоматически.

## 1. Подготовить задачу Linear

В задаче укажите:

- репозиторий `bigbrotherdmitriy-prog/pu-workspace`;
- границы изменения и то, что менять нельзя;
- проверяемые критерии готовности;
- нужные тесты и среду итоговой проверки;
- отдельно — разрешённые внешние действия, если они нужны.

Одна ветка и один PR должны относиться к одной задаче. Не помещайте в задачу пароли, токены, персональные данные и реальные документы клиентов.

## 2. Передать задачу Codex

Создайте ветку по шаблону:

```text
codex/pu-123-short-description
```

Codex должен работать в отдельной чистой worktree, сохранить пользовательские изменения в других ветках и выполнить проверки из критериев готовности.

## 3. Открыть PR

Заголовок PR:

```text
[PU-123] Краткое описание
```

В поле `Linear` шаблона PR оставьте одну каноническую ссылку:

```text
https://linear.app/pu-workspace-ai/issue/PU-123/issue-slug
```

Ключ задачи в заголовке, ветке и ссылке должен совпадать. `package-and-secrets` запускает локальный валидатор `scripts/check_pr_linear_link.py`; он проверяет только идентичность связи, но не существование задачи и не её статус.

## 4. Принять изменение

До merge должны одновременно выполняться условия:

1. все критерии задачи покрыты проверками или приложенными результатами;
2. обязательные checks `test-and-build`, `docker-smoke`, `package-and-secrets`, `python-dependencies`, `frontend-dependencies` успешны на актуальном merge-кандидате;
3. нет секретов и клиентских документов в diff и артефактах;
4. тестовое окружение проверено, если изменение затрагивает пользовательский сценарий.

После merge проверьте, что PR действительно отображается в задаче Linear и её статус изменился ожидаемым образом. Переводите задачу в `Done` только после проверки результата в нужной среде. Репозиторный валидатор сам ничего не публикует и не меняет во внешних системах.

## 5. Локальная проверка контракта

Целевые тесты:

```bash
python -m pytest backend/tests/test_pr_linear_link.py -q
```

Ручная проверка использует сохранённый GitHub `pull_request` event payload:

```bash
python scripts/check_pr_linear_link.py \
  --event-name pull_request \
  --event-path path/to/event.json
```

Для событий, отличных от `pull_request`, проверка намеренно пропускается: на `push` нет заголовка, body и source-ветки PR.
