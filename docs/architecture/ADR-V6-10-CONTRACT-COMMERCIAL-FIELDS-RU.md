# ADR V6-10 Коммерческие поля договора

Статус: утверждено владельцем 05.10.2026. Реализация разделена на два последовательных PR. Merge и production deploy каждого требуют отдельного разрешения.

## Решения

Суммы договора, бюджета, денежного прогноза и счетов включают НДС; на переходах между ними пересчёта нет. НДС задаётся договором в трёх состояниях: не указан, без НДС, ставка, включая 0 %. Счёт не переопределяет ставку.

Исполнение хранится отдельно в `performed_from` и `performed_to`. Гарантия остаётся отдельной конечной датой `warranty_until`. Сумма NULL и ноль допустимы, отрицательная — нет. Предварительный аванс при неизвестной сумме разрешён с предупреждением; при известной сумме аванс не может её превышать. Сумма ноль с положительным авансом недопустима. Дата подписания не в будущем; начало исполнения не позже окончания.

Предложение бюджета запускается явной кнопкой и подтверждается человеком. Сохранение договора не создаёт финансовые записи автоматически.

## V6-10a Поля и ручной ввод

Добавляются `contracts.vat_mode String(20) NOT NULL DEFAULT 'unspecified'`, `vat_rate Numeric(5,2) NULL`, `performed_from Date NULL`, `performed_to Date NULL`. CHECK различает `unspecified/none` с NULL ставкой и `rate` со ставкой от 0 до 100. Это технический диапазон, не справочник действующих налоговых ставок. CHECK срока применяется при двух заполненных границах. Существующий `warranty_until` открывается в PATCH без добавления дублирующей колонки.

На бюджете, ДДС/счёте, акте, платёжном событии и предложениях бюджета/счёта добавляется nullable `vat_snapshot JSON`. SQL NULL означает неизвестное происхождение, не «без НДС». Известный снимок содержит версию формата, режим/ставку и ID/record_version договора. Ставка передаётся десятичной строкой. Старые строки и история не заполняются задним числом.

Новые предложения наследуют текущие условия договора. Изменение режима или ставки НДС делает предложение устаревшим; изменение названия или состава документов без изменения НДС само по себе не мешает подтверждению. Подтверждённые записи не меняются массово. Факт платежа наследует снимок своего счёта/ДДС, не новую ставку договора. Суммы не пересчитываются.

Для неподтверждённой строки бюджета, ДДС или акта доступно явное принятие текущих условий НДС. UI показывает сохранённое происхождение и предлагаемые условия. Сервер проверяет полномочия, статус `proposed`, полный снимок строки, актуальную версию договора и источник; снимок, версия строки и аудит меняются атомарно. Повтор команды с тем же ключом возвращает прежний результат. Сумма, даты, статус и финансовые связи не меняются. Для старых строк этот путь не запускается автоматически и не является backfill.

Валидация ручного сохранения серверная, по итоговому состоянию после PATCH. Сохраняются CAS, видимые ошибки и исходный draft. Реестр и схема открывают одну карточку с документами, структурой, коммерческими полями, историей и явным бюджетным предложением. Расширенный дублирующий список убирается без потери функций.

Денежные поля `amount` и `advance_amount` договора и его бюджетного предложения передаются в JSON канонической десятичной строкой либо NULL. Это исключает потерю копеек при чтении и повторном сохранении допустимого `Numeric(18,2)` через браузерное число. Ввод и отображение сохраняют валюту проекта; бюджетное предложение показывает свою закреплённую валюту. Суммы в БД от этого не меняются.

После этого PR даты вводятся и сохраняются, но проверка финансового периода ещё не введена. Интерфейс явно сообщает об этом; он не утверждает, что финансовые операции уже ограничены этими датами. Новый коммерческий разбор и challenge не входят в этот PR.

## V6-10b Evidence и финансовый период

Разбор основного документа и приложений выдаёт только предложение. Источники закрепляются по текущей версии, SHA-256 текста и составу комплекта. Evidence показывает цитату и документ/версию, пункт или страницу только при доказанном наличии. Источник с явной ссылкой на спецификацию или изменяющим условие дополнением может быть рекомендован приоритетным; необоснованное противоречие остаётся выбором человека. Непроверенное значение не подставляется. Применение — явная команда с CAS и проверкой всех pins; автоматическое коммерческое заполнение прежнего анализатора заменяется этим путём.

Единый серверный финансовый период включителен: нижняя граница `signed_at`, верхняя — max непустых `performed_to` и `warranty_until`. Пустые границы не проверяются; при полностью неизвестном периоде операция разрешена с предупреждением. Бюджету без даты фиктивная дата не назначается.

Выход за период требует prepare/challenge, привязанного к автору, проекту, команде, версиям, источникам и датам. TTL 10 минут. Пользователь вводит причину; повторная серверная проверка, изменение, consume и аудит атомарны. Пакет либо применяется целиком, либо отклоняется с построчным отчётом. Это не ослабляет права, CAS, финансовую цепочку или защиту проведённых записей. Исключение для матричного планового прогноза не распространяется на счета, обязательства и фактические платежи.

## Данные и откат

Миграции аддитивные и не исправляют реальные данные. Перенос значений между удержанием и НДС требует отдельного адресного preview, CAS, причины в аудите и подтверждения владельца, не включён в эти миграции.

Совместимость старых операций отмены проверяется отдельно: динамический snapshot охватывает новые колонки. Новый код нормализует только отсутствующий новый `vat_snapshot` как SQL NULL, не ослабляя сравнение других полей и не переписывая старые receipts.

Возврат старого образа на новой схеме не объявляется безопасным. Основной откат — проверенный восстановлением backup и предыдущий образ в закрытом окне без любых бизнес-записей после backup. Если записи появились, restore потеряет их; требуется остановка записи, сохранение текущего состояния и отдельное решение владельца. Production downgrade не используется автоматически; guard не позволяет удалить заполненные новые данные.

При разрешённой выкатке обязательны финансовая сверка, один SHA/образ для backend, двух durable worker и scheduler, readiness ready:true, неизменный Gmail-флаг и полный manifest всех файлов с публичной HTTPS-сверкой SHA-256 с образом. Диагностика сохраняется при любом исходе.

## Вне объёма

Направления импорта графика, распределение этапов между договорами, правила завершённых/архивных договоров, restore истории, изменение реальных финансовых строк и AUTO — отдельные задачи. Старые суммы и удержания не интерпретируются по догадке.
