# Ограниченное продление mailbox authority

Это не продление AUTO policy и не запуск пилота. Разрешённый владельцем PR
добавляет отдельный ручной путь восстановления после OAuth-переподключения.

## Контракт

`POST /api/integrations/mailbox-authority/renew`, авторизованный текущий владелец,
`If-Match: "<authority_version>"`. Тело: organization_id, project_id,
mail_connection_id, credential_generation, binding_epoch, valid_until с timezone,
approval=CONFIRM, reason=owner_confirmed_project_reconnect.

- Только существующая active-запись того же пользователя; истечение допускается,
  revoked/отсутствующая запись — отказ. Администратор без роли owner не подходит.
- Проверяются текущая подтверждённая Google identity и принадлежность credential
  выбранному проекту. Нельзя переносить допуск на другой проект.
- Права не добавляются; разрешены только прежние ingest/read/rollout.
- Новое истечение позднее старого и не далее 24 часов от серверного времени.
- Допуск сужается до project + generation. Ротация делает его непригодным.
- Включить primary_read/actions или выполнять внешние действия этим допуском нельзя.
- Обновление версии, срока, scope и запись audit выполняются одной транзакцией.
  Повтор со старым If-Match — 409; это не повод повторять запрос с новой версией.

## Миграция и откат

c70a0090f001 после c70a00a2f001 добавляет два nullable поля scope.
Существующие записи не продлеваются и не активируются. При downgrade все scoped
допуски отзываются с увеличением версии **до** удаления полей: иначе откат расширил
бы полномочия до всего ящика. Перед production — backup и отдельное разрешение.

## Последующий rollout проекта 17

После отдельного решения о merge/deploy проверить текущую generation заново.
Затем вручную выполнить подтверждённое продление и CAS переходы shadow_write,
shadow_read_compare, pilot_write, включить cohort только проекта 17.
primary_read/actions остаются false. Другие проекты, старые generation,
AUTO policy и project authority не меняются.

Этот PR не исправляет происхождение уже созданного письма №36746, не выдаёт
reconcile и не подставляет mailbox/source refs. Восстановление происхождения
требует отдельной проверки штатного reconciliation, без дубликата письма.
До этого запуск AUTO и начало пятидневного окна не подтверждены.
