# MVP5 — стабилизация архитектуры v5.2

MVP5 не добавляет второй набор поставщиков. Его цель — сделать текущий рабочий
Vertical Slice 1 устойчивым и подготовить Core к подключению заменяемых адаптеров.

## Границы

- сохранить работающие Google Workspace, Gmail, Telegram и Gemini;
- не переносить vendor-specific модели и SDK в Project/Document/Contract/Task Core;
- показывать пользователю фактическое, а не только конфигурационное состояние;
- сохранять выбранный проект во всех переходах и фоновых обновлениях;
- не изменять оригиналы и не выполнять внешние действия без подтверждения.

## Приёмка

- [x] активный проект устойчив к OAuth, выбору источника и гонкам обновления;
- [x] API подтверждения задач использует provider-neutral команды с legacy aliases;
- [x] каталог интеграций формируется отдельным integration layer;
- [x] Google scopes проверяются внутри GoogleWorkspaceAdapter;
- [x] Telegram relay health отличает настроенный токен от рабочего polling;
- [x] секрет Telegram не попадает в health и журнал ошибок;
- [ ] production regression после обновления каталога;
- [ ] устранён внешний второй polling-процесс Telegram и заменён раскрытый токен.

Последний пункт требует выпуска нового токена через BotFather и остановки старого
Replit/иного процесса, использующего тот же бот. Это эксплуатационная операция,
а не изменение PU Workspace Core.
