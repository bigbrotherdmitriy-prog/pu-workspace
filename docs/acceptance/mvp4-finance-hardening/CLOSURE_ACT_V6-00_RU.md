# Акт закрытия MVP-4 / V6-00 (Шаг 10 плана закрытия)

Дата независимой сверки: 07.10.2026. Метод: read-only запросы к production-БД (`puw-primary-next-primary-db`), независимо от кода приложения. Полигон выверки сумм — проект №17 (договор Б-УЗП130-02-2026); полигон сквозного прогона (приёмочный) — проекты №17 и №24.

Критерий приёмки MVP-4 (из плана закрытия, неизменный): «MVP-4 считается закрытым, когда на проекте №17 одновременно выполнено» шесть пунктов ниже.

## 1. Снапшот ДДС совпадает с итогами на экране по каждому месяцу и в целом

Подтверждено. Помесячная раскладка и итог (677 750 000,00 ₽ приход / 405 828 883,69 ₽ расход), показанные в UI («Таблица ДДС», «Детализация»), совпали с прямой выборкой из `cash_flow_entries` в ходе совместного прохождения с владельцем 07.10.2026 — сверено построчно, включая разбивку по месяцам (март–октябрь 2026).

## 2. Все записи ДДС либо подтверждены, либо осознанно отменены

Подтверждено прямым запросом:

```sql
SELECT project_id, contract_id, direction, status, count(*), sum(planned_amount)
FROM cash_flow_entries WHERE project_id IN (17,24)
GROUP BY project_id, contract_id, direction, status;
```

Результат — только статусы `approved`, `paid`, `cancelled`. Ни одной записи в статусе `proposed` не осталось ни на проекте №17, ни на проекте №24.

## 3. Каждая подтверждённая запись привязана к договору и строке бюджета

Подтверждено:
- Проект №17, договор id=25, расход: 77 из 77 записей имеют и `contract_id`, и `budget_line_id` (через допустимое исключение §27.1 — `entry_kind='plan_forecast'`, матричный импорт, без прямого `schedule_item_id`).
- Проект №17, договор id=25, приход: 11 из 11 записей привязаны к договору и к строке бюджета id=36 («Доходная строка, проект №17») — после переноса через новый эндпоинт backfill (`POST /execution/cash-flow/{id}/link-budget-line`, PR #129), созданный специально для этого класса исторических записей.
- Проект №24, договор id=41: 2 из 2 оплаченных записей привязаны к договору, строке бюджета id=34 и этапу ГПР #827.

## 4. Суммы сходятся с исходным Excel до копейки (эталон расходов 405 828 883,69 ₽)

Подтверждено точным совпадением:

```sql
SELECT count(*), sum(planned_amount) FROM cash_flow_entries
WHERE project_id=17 AND contract_id=25 AND direction='outflow' AND status='approved';
-- 77 | 405828883.69
```

Совпадает с эталоном до копейки. Сумма прихода (677 750 000,00 ₽, 11 записей) также подтверждена независимым запросом и равна плановой сумме строки бюджета id=36.

## 5. Сквозной прогон Договор → Бюджет + ГПР → Счёт → ДДС → Платёж проходит без ручных обходов

Подтверждено. Расходная ветка проекта №24 (договор №03-2026) пройдена полностью штатными средствами: Договор → Бюджет (строка id=34) → этап ГПР #827 → ДДС → Платёж (`status=paid`, `actual_amount=planned_amount`). Доходная ветка проекта №17 закрыта через намеренно построенный узкий механизм backfill (не обход, а предусмотренная функциональность для исторических записей, созданных до появления доходных строк бюджета).

Два дефекта, найденные и устранённые в ходе этого же прогона (не воркэраунды, а штатные фиксы с тестами и PR):
- отсутствие поля «Направление» в форме ручного добавления строки бюджета (PR #127);
- ложное срабатывание regex-распознавания ставки НДС на реальном договоре №03-2026 (PR #128).

## 6. Независимая сверка подтверждает пункты 1–5 запросами к production-БД

Выполнена — это и есть данный акт. Все запросы — read-only, выполнены напрямую к `puw-primary-next-primary-db`, независимо от кода приложения и без участия UI в формировании результата (UI использовался только для сравнения со снапшотом в пункте 1).
