## 1. Продукт и ценность

### 1.1. Что это

**PU Workspace** — органайзер проектных документов для подрядных, проектных, строительных и сервисных компаний. MVP обеспечивает безопасную работу с проектной документацией в облачном хранилище:

`выбор папки → безопасная копия → анализ → предложение → подтверждение → применение → журнал → откат`

Ключевой инвариант: **органайзер не изменяет исходную папку**. Все перемещения и переименования происходят только внутри созданной копии. Точные дубли и предполагаемые версии не удаляются; неоднозначные случаи требуют явного подтверждения человеком.

### 1.2. Проблема клиента

> «Договоры — в папках, сроки — в календаре, деньги — в Excel, письма — в ящике. Никто, кроме двух-трёх людей, не видит целостной картины. Сроки теряются, обязательства закрываются с опозданием, руководитель каждый день вручную собирает свою картину из 5 источников».

Целевой сегмент: **подрядные, проектные, строительные и сервисные компании от 20 до 200 человек, с 3+ параллельными проектами**. ЛПР — собственник/гендиректор (до 100 чел.) либо руководитель проектного офиса / коммерческий директор (свыше 100).

### 1.3. Ценность и охват функций (по брифу)

Готово и работает:
- Ядро обработки документов с подтверждением и откатом.
- Интеграции с Google Drive, Яндекс Диском, Telegram.
- Загрузка файлов с компьютера.
- Android-оболочка.
- Бэкапы (шифрованные, в Google Drive), watchdog, uptime-мониторинг, Telegram-алерты.
- Роли и доступы: `viewer`, `member`, `editor`, `manager`, `owner`. Проверка прав — не только на список проектов, но и на вложенные session/proposal/action/document/history/Drive-ресурсы. Глобальный аудит и правила — только администратор.
- Bearer-сессии с истечением и автоочисткой при старте и выдаче новой сессии.

Не готово (критические разрывы перед коммерцией):
- **Мультиарендность** — частичная: `organization_id` присутствует у 14 из 39 моделей.
- **Публичная регистрация / онбординг** — нет.
- **Оплата** — нет.
- **152-ФЗ** — юридические документы и уведомление РКН отсутствуют.
- **Коннектор офисного сервера** (Windows-служба / Synology) — нет.

### 2.3. Безопасность и изоляция

- **Роли проекта:** `viewer`, `member`, `editor`, `manager`, `owner`.
- **Проверка прав** выполняется не только для списка проектов, но и для вложенных session, proposal, action, document, history и Drive-ресурсов.
- **Администратор** — единственный, кто видит глобальный аудит и правила.
- **Bearer-сессии** — удаление истёкших при старте приложения и при выдаче новой.
- **Первый администратор** создаётся по `BOOTSTRAP_TOKEN` (≥ 24 символов) через экран «Первый запуск».
- **Fernet-ключ** для токенов генерируется отдельной командой и хранится в `.env`.
- **2FA (TOTP), журнал аудита действий, IP-ограничения, расширенный RBAC** — по брифу ещё не реализованы.

### 2.4. Инфраструктура (по брифу)

**Сейчас:** 1 сервер — 3.8 ГБ RAM, 48 ГБ SSD, Postgres 16 в Docker, IP 72.56.108.162 (Timeweb Cloud). **Домен — `puworkspace.ru` (уточнить статус регистрации и владельца).**

**План под 10 клиентов:** апгрейд до 8 ГБ RAM / 160 ГБ SSD; ежедневный бэкап в S3-совместимое хранилище РФ. Ориентир: 1 500–2 500 ₽/мес (допущение).

**План под 50 клиентов:** выделенный app-сервер (16 ГБ RAM) + отдельный сервер БД (16 ГБ RAM, SSD 500 ГБ); read-only реплика Postgres; S3-хранилище 100–500 ГБ. Ориентир: 12 000–20 000 ₽/мес (допущение).

**Масштабные пороги** (из брифа):
- 10 клиентов → RAM 8 ГБ, отдельный бэкап-контур, статус-страница.
- 25 клиентов → отдельный сервер БД, реплика, CDN для статики.
- 50 клиентов → второй app-сервер за балансировщиком, реплика БД, алерты на диск/CPU/латентность.
- 100+ → K8s или эквивалент, S3 как основное хранилище файлов.

### 2.5. Бэкапы и мониторинг

- **Бэкапы:** шифрованные, в Google Drive — работают.
- **Мониторинг:** watchdog, uptime, Telegram-алерты — работают.
- **Не сделано по брифу:** бэкап в российское S3-совместимое хранилище, регламент восстановления и ежемесячная проверка восстановления.

### 2.6. Развёртывание

- **Docker Compose.** Перед стартом backend контейнер применяет версионируемые миграции Alembic.
- **Локальный запуск:** `scripts/setup-local.ps1` создаёт `.env` со случайными секретами (не перезаписывает существующий без `-Force`); redirect URI для Google — `http://localhost:3000/projects/google/callback`.
- **Google OAuth** — внесены сообщения о необходимости restricted scopes для публичного распространения; в бриф это отнесено к отложенным задачам.

## 4. Права на код

### 4.1. Авторство по git

По данным git:
- **Codex \<codex@openai.com\>** — 673 коммита.
- **Codex \<codex@users.noreply.github.com\>** — 6 коммитов.
- **bigbrotherdmitriy-prog \<bigbrotherdmitriy@gmail.com\>** — 222 коммита.
- **bigbrotherdmitriy-prog \<305048587+bigbrotherdmitriy-prog@users.noreply.github.com\>** — 3 коммита.
- **Dmitriy \<bigbrotherdmitriy-prog@users.noreply.github.com\>** — 1 коммит.

Итого: **два фактических автора-человека (один из них владелец) и ИИ-ассистент Codex (OpenAI)**. Авторство в коммитах Codex не создаёт прав у OpenAI на код как таковой, но требует проверки условий использования ИИ-провайдера (см. 4.3).

### 4.2. Уведомление о лицензии

`LICENSE` в корне — коммерческое уведомление:

```
PU WORKSPACE — COMMERCIAL SOURCE CODE NOTICE
Copyright (c) [ТРЕБУЕТ ДАННЫХ ПРАВООБЛАДАТЕЛЯ: полное наименование/ФИО и год].
All rights reserved.
```

**Правообладатель не указан.** Это критический пробел для любой сделки.

### 4.3. Что нужно оформить

1. **Создать/определить ЮЛ-правообладателя** (ООО по РФ) и зафиксировать в `LICENSE` его полное наименование, ОГРН, год.
2. **Договор(ы) об отчуждении исключительного права** на ПО:
   - от физлица-владельца (и любого другого физлица-соавтора, если коммиты под иными именами писались другими людьми) в пользу ООО;
   - включить все версии/ветки/историю git как объект отчуждения.
3. **Проверка лицензий ИИ-провайдеров.** Сверить условия использования OpenAI Codex (и любых иных использованных ИИ — Claude/Gemini/DeepSeek по брифу):
   - допускается ли коммерческое использование сгенерированного кода;
   - нет ли ограничений на передачу прав третьим лицам;
   - сохранён ли запрет обучения/воспроизведения чужого кода без указания авторства;
   - зафиксировать дату/версию ToS на момент передачи.
4. **Отсутствие заимствованного кода** из репозиториев с копилефт-лицензиями — подтвердить сканером (например, SCA-инструментом и/или ручным сравнением крупных файлов).
5. **Учёт НМА** — поставить ПО на баланс ООО и учесть как нематериальный актив после передачи прав.
6. **Товарный знак «PU Workspace»** — заявка в Роспатент. Срок по брифу: **4–12 месяцев**, бюджет **50 000–150 000 ₽ (допущение)**.
7. **Регистрация ПО в реестре отечественного ПО (Минцифры)** — даёт покупателю-интегратору льготы и доступ к госзакупкам. **Преимущества по брифу — уточнить/проверить с профильным юристом**; срок 2–4 месяца.
8. **NDA-шаблон** для пилотов и переговоров, **DPA/поручение на обработку ПДн** — обязательны до передачи любому покупателю.
