# Схема разработки: минимальное участие владельца, Gemini + Claude

Дата: 2026-10-06. Статус: принято, действующая схема.

## Роли

- **Владелец (вы)** — задаёт/правит ТЗ, тестирует готовый результат на staging, даёт фидбек по сути (не по технике). Решает про production-промоушен и любые действия с реальными деньгами/доступами/необратимые.
- **Gemini** (Pro + API, отдельный ключ — не production-ключ приложения) — исполнитель объёма: код по детальному ТЗ, тесты, рефакторинг, черновики документации, массовые правки, исследование большого контекста.
- **Claude (эта сессия)** — оркестратор и контроль: формулирует точные ТЗ для Gemini, проверяет критичные/рискованные утверждения эмпирически (а не на слово), прогоняет гейты (regression, secrets scan, миграции), готовит PR, просит подтверждения перед commit/push/merge.

## Окружения (важно, зафиксировано в коде проекта)

| Среда | Адрес | Как обновляется | Назначение |
|---|---|---|---|
| **Staging** | `37.252.23.204` | Автоматически: merge в `main` → `ci`/`docker-smoke`/`security`/`staging-preflight` зелёные → GitHub Actions сам по SSH (свой секрет, не наш) деплоит | Быстрый цикл разработки и тестирования |
| **Production** | `72.56.108.162` | Только вручную, осознанно (`scripts/deploy-primary-first-host.sh` и т.п.) | Live AUTO-пилот project_id=17, реальные данные/права — **намеренно защищён от авто-деплоя** (`scripts/validate_staging_settings.py` жёстко отказывается деплоить staging-пайплайном на этот адрес) |

**Правило**: весь цикл быстрой разработки и тестирования идёт через staging. Production обновляется отдельным, явным, вручную инициированным шагом — не автоматически, не как часть обычной итерации.

## Рабочий цикл

```
1. Владелец формулирует/правит пункт ТЗ (коротко, по-человечески).

2. Claude переводит его в точную техническую задачу:
   - малое/точечное — делает сам напрямую;
   - большое/объёмное (много файлов, boilerplate, долгое
     исследование) — формулирует детальный промпт для Gemini.

3а. [Gemini-ветка] Владелец переносит промпт в Gemini
    (или Claude сам вызывает Gemini API — отдельным ключом,
    когда он будет готов) → Gemini делает объём.

3б. Результат Gemini (diff/код) возвращается Claude для проверки —
    не как сырой лог целиком, а как сохранённый diff/файл.

4. Claude:
   - применяет/дорабатывает изменения,
   - прогоняет regression + secrets scan + (если нужно) миграции,
   - готовит коммит/PR, показывает что получилось,
   - ждёт подтверждения перед commit/push.

5. После merge в main — автоматический деплой на staging
   (ничего делать не надо).

6. Владелец открывает staging, тестирует, даёт фидбек
   в свободной форме → возврат к шагу 1.

7. Когда накопился готовый, проверенный набор изменений —
   отдельное, осознанное решение владельца: промоушен в production
   (72.56.108.162), с ручным шагом, не автоматически.
```

## Экономия токенов Claude

- Не вставлять в чат сырой длинный вывод (логи, HTML-дампы) — складывать в файл, Claude читает файл сам.
- Приносить уже отфильтрованный результат («137 passed, 2 failed: вот эти два»), а не процесс целиком.
- Крупные автономные куски работы — через Gemini, не через Claude.
