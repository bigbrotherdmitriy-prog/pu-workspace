# Состав сделки и границы релиза

## Четыре самостоятельных объекта

| Объект | Что это | Входит по умолчанию |
|---|---|---|
| PU Workspace Core | исходный код Core и общие модули на зафиксированном SHA | только если отмечен в Спецификации |
| Клиентский релиз | отобранный архив, миграции, конфигурационные шаблоны и документация | да, в точном составе manifest |
| Бренд | название, логотип, домены, товарные знаки, рекламные материалы | нет |
| Будущие версии | commits, функции, адаптеры и исправления после SHA Акта | нет |

Передача экземпляра исходного кода не равна передаче исключительного права. Передаваемые способы использования перечисляются исчерпывающе в подписанном договоре. Для отчуждения исключительного права требуется отдельный договор и отдельная спецификация объекта.

## Технический состав коммерческого архива

Архив формируется только из commit SHA: backend/frontend runtime source, миграции, безопасные шаблоны, документация, `LICENSE`, `NOTICE`, SBOM и release manifest. Исключаются тесты с клиентоподобными фикстурами, `.env`, ключи, токены, production/deploy-доступы, backups, логи, пользовательские файлы, sales-материалы, `.git` и `node_modules`.

Точный состав определяется исключительно `RELEASE_MANIFEST.json`; разночтения со списками в договоре устраняются до подписания Акта. Manifest считается принятым только вместе с успешным `VERIFICATION_RESULT.json`, созданным по процедуре [REPRODUCIBLE_PACKAGING_RU.md](REPRODUCIBLE_PACKAGING_RU.md). Python и контейнерные зависимости подтверждаются отдельными provenance/evidence, а не тегом образа или текущим состоянием package registry.
