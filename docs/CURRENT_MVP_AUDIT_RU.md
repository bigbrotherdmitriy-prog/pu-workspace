# PU Workspace — аудит демонстрационного MVP

Дата проверки: 30 августа 2026 года.

## Проверенная базовая линия

- ветка разработки: `codex/mvp-safe-organizer-v1`;
- backend: 185 тестов прошли;
- frontend: `pnpm run check` и `pnpm run build` прошли;
- provider-neutral мастер запуска связывает проект, безопасную рабочую копию,
  документы, договор, ГПР/бюджет/ДДС и подтверждённые контакты;
- готовность источника учитывает реальные завершённые статусы органайзера
  `proposed` и `applied`, а также legacy-статусы;
- оригиналы не должны изменяться до подтверждения, внешние действия проходят
  через пользовательское решение и аудит.

Проверка не заменяет отдельный production smoke после каждого развёртывания и
не подтверждает доступность внешних Google, Telegram или AI API без живых
учётных данных.

## P0 — блокирует работу

На проверенной локальной базовой линии кодовых P0 не обнаружено. Перед каждым
production-релизом обязательны резервная копия БД, миграции, readiness и smoke
ключевого сценария.

Эксплуатационный P0 при его актуальности: заменить ранее раскрытый Telegram
token через BotFather и остановить второй polling-процесс. Секрет нельзя
восстанавливать или хранить в репозитории.

## P1 — необходимо для сильного MVP

- поддерживать один демонстрационный путь через «Запуск проекта»;
- не считать папку готовой до появления безопасной копии и завершения анализа;
- показывать источник для договора, обязательства, риска и задачи;
- проверять сценарий «проект → документ договора → анализ → обязательство →
  задача/риск → внимание руководителя» перед демонстрацией;
- сохранять актуальные инструкции запуска, миграций, тестов и отката;
- не заявлять внешний адаптер или AI-возможность без рабочего подтверждения.

## P2 — улучшает продукт

- продолжить декомпозицию `frontend/src/App.tsx` по доменным модулям;
- добавить браузерный smoke-тест главного демонстрационного сценария;
- добавить компонентные UI-тесты мастера запуска и карточки договора;
- вынести очередь анализа во внешний broker перед горизонтальным масштабированием;
- улучшить наблюдаемость: correlation id, структурированные ошибки и метрики
  длительности анализа.

## P3 — следующему владельцу / отдельные вертикальные срезы

- дополнительные Storage/Channel/Integration/AI adapters;
- enterprise Shared Drives и расширенная DLP;
- production OCR/vision для сложных сканов;
- PWA или нативные мобильные клиенты;
- специализированные агенты поверх устойчивого Core.

## Десятиминутная демонстрация

1. Открыть существующий демонстрационный проект.
2. В «Запуске проекта» показать источник и безопасную копию.
3. Открыть каталог документов и результат анализа.
4. Открыть договор с привязанным документом-источником.
5. Показать извлечённые обязательства, сроки и риски с provenance.
6. Подтвердить одну предложенную задачу или решение.
7. Вернуться в рабочий центр и показать обновившийся блок внимания.

Для продажи демонстрационные данные должны быть синтетическими и не содержать
персональных данных, production credentials или документов действующих клиентов.
