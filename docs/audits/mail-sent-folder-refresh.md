## Диагностика

Read-only SSH на разрешённый VPS 72.56.108.162 показал backend image
`app-backend:7e1a1d4901931c708d184f805ebee4a845df7dd3`.
Проверено дерево этого локально доступного SHA: отсутствует gmail.modify;
7e90ccf не является его предком. Это объясняет, почему подготовленный локально
mail move fix ещё не изменил работу сайта. Данные токенов/писем не читались.
Workers/scheduler остаются на 8e674ec, relay на 9825fa0: для выпуска требуется
координация текущего runtime, а не слепое переключение на старую ветку.
HTTPS status из локальной PowerShell не удалось прочитать из-за TLS-ошибки;
проверка сертификатов не отключалась. Runtime evidence — версия Docker image,
не утверждение о действующих OAuth scopes конкретного аккаунта.

Кнопка обновления вызывала одинаковый `newer_than:7d, max_results:25`, даже в
папке sent. Backend распознаёт SENT, но письмо должно сначала попасть в выборку.
Счётчик интерфейса — локальные записи проекта, а не полный размер папки Gmail.
Нулевой счётчик не доказывает отсутствие писем в Gmail.

## Исправление

- MailClientModule передаёт выбранную папку в существующий callback.
- App использует bounded query выбранной папки. Sent: `in:sent`, без ограничения
  последними семью днями; inbox/spam/trash/archive/all получают свои запросы.
- Фоновое обновление и вызовы без папки остаются `newer_than:7d`.
- Все запросы ограничены 25 письмами. Это НЕ полная синхронизация истории.
- Сообщение пустого списка говорит об отсутствии загруженных писем, не о пустом Gmail.
- Реальные письма не отправлялись, не удалялись и не импортировались этой задачей.

## Интеграция и ограничения

В соседних ветках есть Gmail pagination/history/full-resync (включая 8f093c5).
Они изучены только read-only; их реализация не дублировалась и не переносилась.
При интеграции сохранить новый scope fix 7e90ccf и точечный folder callback,
согласовав его с новым sync API. Не переносить старые compiled assets поверх
текущего дизайна: пересобрать единый интеграционный commit.

Проектная семантическая маршрутизация остаётся существующей: письма другого
подтверждённого проекта не отображаются в текущем. Полная история и отдельный
mailbox-wide обзор не реализуются здесь. Проверка live Gmail остаётся необходимой.

Push/deploy не выполнялись. До выпуска — CI точного объединённого SHA, согласование
с владельцем runtime, backup/rollback и CAS текущего релиза. После выпуска пользователь
повторно подтверждает Google consent для gmail.modify в том же аккаунте/проекте.
