## Граница V3-04a

V3-04a обнаруживает пересечения встреч только по структурированным участникам
(`user_id` / `contact_id`) и полуоткрытым временным интервалам. Создание встречи
не блокируется: API и интерфейс возвращают предупреждение.

## Реализованная граница V3-04b1

- tenant-scoped каталог помещений, техники и других бронируемых ресурсов;
- одна организация владеет идентичностью ресурса, один проект управляет им;
- manager управляющего проекта создаёт, меняет и деактивирует ресурс;
- `active=false` запрещает новые бронирования, не уничтожая историю;
- ресурс прикрепляется к встрече структурированным `resource_id`;
- пересечения вычисляются по полуоткрытым интервалам `[start, end)` и дают
  предупреждение, но не блокируют встречу;
- отменённые встречи исключаются;
- вместимость является metadata и даёт отдельное предупреждение, а не блок;
- конфликт другого проекта той же организации редактируется по тем же правилам,
  что и конфликт участника;
- конкурентные бронирования одного ресурса сериализуются блокировкой строки
  ресурса `FOR UPDATE`.
