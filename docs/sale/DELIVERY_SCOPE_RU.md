# Состав поставки и границы ответственности

## Входит

- конкретный git commit и контрольная сумма архива;
- исходный код frontend/backend и миграции БД;
- Dockerfile, Docker Compose и production deployment script;
- автоматические тесты;
- техническая и пользовательская документация;
- пример конфигурации без действующих секретов;
- акт проверки функций по `HANDOVER_AND_ACCEPTANCE_RU.md`.

## Не входит

- production-сервер продавца, домен и резервные копии;
- персональные данные, документы и письма продавца;
- действующие OAuth credentials, токены, пароли и ключи шифрования;
- аккаунты Google, Telegram, Gemini или иных поставщиков;
- лицензии и платежи сторонним поставщикам;
- перенос данных покупателя, обучение, сопровождение и SLA;
- будущие версии основной ветки и новые функции;
- гарантия совместимости с будущими изменениями сторонних API.

## Приёмочный период

Рекомендуемый срок — 10 рабочих дней. Проверяются только функции, перечисленные в акте. Критический дефект — невозможность запустить систему или выполнить согласованный основной сценарий в эталонной среде. Новые требования не являются дефектами и не входят в приёмку.

## После приёмки

Покупатель самостоятельно отвечает за инфраструктуру, безопасность, резервное копирование, обновления зависимостей, доступность сторонних API и соблюдение законодательства при обработке данных.
