# NOTES — допущения

## Offline logout — 04.11.2026

- [ДОПУЩЕНИЕ] HttpOnly-cookie физически недоступна JavaScript. Офлайн блокируем её использование всеми API/автовходом, удаляем доступные cookie и ownedcache; после сети отзываем исходную SQLсессию. Даже оставшаяся HttpOnlycookie после отзыва недействительна. Нельзя обещать физическое удаление HttpOnly офлайн.
- [ДОПУЩЕНИЕ] Несинхронизированные команды/фото/stockintents сохраняются под прежним actor до явного входа; перед выходом всегда предупреждаем. Это приоритетнее прежнего default destructivepurge. Вход другогоactor их не отправляет.
- [ДОПУЩЕНИЕ] В durablequeue хранится capability ТОЛЬКОотзыва конкретной сессии, не пароль/входнойtoken/CSRF. Она выдаётся сервером приlogin/подготовкеактивногосеанса, не позволяетauth/получениеданных, не выводитсявлоги. Endpoint безSet-Cookie не может позднимответом стереть новуюcookie другогоlogin.
- Runtimeчасти должны поставлятьсясовместно, productiondeploy не выполняется. Никакой миграции/нового serversecret нет.

## Проверки и сохранение данных — 05.11.2026

- [ДОПУЩЕНИЕ] «Не потерять несинхронизированные данные» означает сохранить уже записанные в IndexedDB команды, фото Blob и складские операции под прежним пользователем. Текст ещё не сохранённой формы может быть потерян: диалог выхода прямо предупреждает сохранить его до подтверждения. Отмена диалога ничего не очищает.
- [ДОПУЩЕНИЕ] После выхода, явного нового входа и восстановления страницы из BFCache всё приватное React-состояние пересоздаётся. Одной блокировки запросов недостаточно: ранее открытые документы не должны оставаться на экране.
- Реальные .env/ключи не читались. Для полного набора восстановлены точные Git blobs публичного .env.example с placeholder-значениями и общедоступные исходники тестовой инфраструктуры. Тестовый guard разрешает только новые synthetic env-файлы, созданные этим процессом под его pytest tmp-каталогом, включая атомарное переименование.
- Полный backend запускается с memory SQLite; PostgreSQL conditional tests остаются SKIP и не выдаются за новую PG-приёмку. Java-парсер использует временный JRE и heap192MB. Production/БД/службы не менялись.
- Прежние migration revision-файлы не изменены. Только offline SQL export теперь явно отказывается от диапазона, который требует проверки живого каталога; online migration path не менялся и в этом задании не запускался.
- Codex fallback: DeepSeek не исполнил это исправление; ограничение контекста App и отклонённый DS53 зафиксированы ранее. Все новые коммиты помечены как Codex, не результат модели.

- Поздний ответ проверяется дважды: после fetch и после await response.json. Найдена и воспроизведена гонка завершения JSON после выхода (11PASS/1FAIL до исправления →18targeted PASS после). Одной проверки HTTP-заголовков недостаточно.
- Два новых Playwright-сценария на полном App выполнены: offline logout и reload со старой HttpOnly-cookie. Health probe с query-параметром в offline сценарии явно отклоняется mock; первый ошибочный glob в тесте исправлен. Mock API не выдаётся за настоящий сервер; отдельные4 Chromium→actualHTTP checks покрывают серверную часть.

- [ДОПУЩЕНИЕ] Под очисткой кэша реализована очистка принадлежащих приложению CacheStorage `pu-workspace-*` и всех приватных React-полей. JavaScript не предоставляет универсальной очистки дискового HTTP-кэша браузера; не обещаем её. API-клиент всегда использует `cache: no-store`, а local/server fence запрещает восстановление сеанса. Сохранённые очереди и оригиналы неотправленных фото намеренно не считаются удаляемым кэшем.
