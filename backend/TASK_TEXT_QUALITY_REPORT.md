## Причина и путь данных

`organizer_engine/content.py` извлекает native/OCR/hybrid текст, возвращая
ExtractionResult с грубой quality по длине и доле букв/цифр. Plain-text facade
`extract_text()` оставляет только текст. `StorageObject.content_text` не несёт
OCR confidence. Local upload, Gmail attachments и другие существующие consumers
передают этот текст в `create_tasks_from_files` → `extract_task_candidates`.

Ранее в task_engine confidence = 0.90 при распознанной дате, иначе 0.82:
повреждение текста не учитывалось. Проверка качества добавлена на уровне
фрагмента TaskCandidate; она не пытается восстановить отсутствующие OCR metadata
и не штрафует все задачи документа из-за одного повреждённого предложения.

## Изменения

- `backend/app/task_engine.py`: необязательное `TaskCandidate.review_reasons`,
  консервативный детектор, потолок оценки 0.45 при наличии сигналов повреждения,
  понятная причина в существующем `Task.description`.
- `backend/tests/test_task_text_quality.py`: 44 синтетических проверки.
- `backend/TASK_TEXT_QUALITY_REPORT.md`: этот отчёт и контракт интеграции.

Детектор отмечает U+FFFD, служебные/private-use знаки, характерные повторяющиеся
пары сломанной UTF-8 кодировки, длинные последовательности отдельных строчных
букв, шестикратный повтор буквы, скопление шумовых символов и несколько слов
с одиночными внутренними подменами кириллицы латиницей/цифрой. Последний сигнал
требует минимум двух подходящих слов, а не произвольного mixed-script токена.
Даты, числа, uppercase сокращения, артикулы и многочастные коды сами по себе
не являются признаком повреждения. Словаря «разрешённых технических слов» нет.

Наличие даты не отменяет снижение. Для нормальных фрагментов сохранены 0.82/0.90
ради совместимости. Все эти числа — **эвристические баллы, не калиброванная
вероятность и не измеренная точность OCR**. 0.45 — порог приоритета проверки,
не утверждение о 45% правильности.

Кандидаты с признаками повреждения не отбрасываются и не исправляются догадками.
Сохраняются source_file_id/name, source_excerpt/hash и связь Obligation→Task.
Нынешняя нормализация пробелов/разбиение предложений не менялись; цитата —
извлечённый фрагмент, не копия исходных PDF bytes или доказательство координат.
Дата остаётся извлечённой, а не подтверждённой. needs_review=True,
external_action_status=proposed, Obligation.status=needs_confirmation.
Новые пользователи/исполнители не выводятся из текста; прежний выбор existing
project assignee не менялся. Автоподтверждения и внешнего исполнения нет.

## Минимальный контракт интеграции API/UI (не реализован в этой ветке)

GET `/tasks` сейчас не возвращает `Task.description`. Причина сохранена в БД,
но сама по себе эта правка не гарантирует её отображение в текущем интерфейсе.
Для интегратора, после согласования:

1. Additive поле `description: string | null` в task list response, из уже
   существующего столбца. Не парсить русский текст в машинные reason codes.
2. UI показывает описание рядом с `needs_review`, ссылку/цитату существующего
   документа. Confidence подписывать «эвристическая оценка», не «вероятность»
   или «точность OCR»; отсутствие сигналов не означает «распознано верно».
3. Если нужны стабильные structured reason codes/versioned assessment,
   согласовать отдельный контракт хранения/API; новый столбец или миграцию
   эта ветка не добавляет. `review_reasons` сейчас внутренний tuple кандидата.

## Ограничения и старые задачи

- Нет семантической проверки: правдоподобно написанная неверная дата/сумма или
  бессмысленный кириллический текст без явных сигналов могут не обнаружиться.
  Это не benchmark OCR precision/recall и не основание для юридических действий.
- Возможны ложные тревоги на декоративной разрядке, private-use шрифтах,
  масках из символов и редких строчных кодах, похожих на два повреждённых слова.
  Они остаются видимыми для ручной проверки; текст не переписывается.
- Полностью испорченное слово обязательства может не совпасть с прежним
  OBLIGATION_RE. Существующие ограничения 18–1200 знаков, разбиение на
  предложения (включая точки сокращений), максимум 5 кандидатов не расширены.
  Детектор не вводит нового скрытого фильтра обязательств.
- Неподдерживаемые БД управляющие знаки (например NUL для PostgreSQL) эта
  эвристика обнаруживает, но не меняет их сериализацию/хранение: это отдельный
  ingestion-контракт, не повод молча удалять знаки из доказательства.
- Старые записи **не пересчитываются**. Повторный импорт того же file/excerpt
  возвращает прежнюю запись по dedup, не меняя confidence, review, description
  или ручные правки. Это покрыто тестом. Исторические 82% остаются до отдельного
  согласованного пересмотра; этот commit не является data migration.
- Deploy/merge/push не выполнялись. Один отдельный commit; интеграция UI и
  проверка на PostgreSQL остаются отдельными шагами.
