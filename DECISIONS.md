# Предварительные решения — 04.11.2026

Статус каждого пункта: **«предварительное решение, требует подтверждения»**. Пользователь поручил реализовать безопасные значения по умолчанию и продолжать синтетические проверки. Это не продуктовая приёмка и не разрешение production.

| Область | Безопасное значение по умолчанию | Настройка и границы |
|---|---|---|
| Сметная цена из суммы/количества | Не менять исходный total молча; если округлённая цена не воспроизводит его до копейки — требовать явную цену | `PU_ESTIMATE_ROUNDING_POLICY=reject_ambiguous`; альтернативное явное `round_half_up` сохраняет исходный total, допускает отмеченное расхождение. Явная цена всегда имеет приоритет при КС. |
| Физический остаток | Запретить расход сверх поступлений минус уже проведённый расход | `PU_NEGATIVE_STOCK_POLICY=forbid`; альтернативное `allow_explicit` только при явной настройке, без вывода прихода из оплаты. |
| Списание | Только отдельная команда с материалом, записью журнала, количеством и idempotency key; исправление — отдельное сторно | Никакого автоматического списания по объёму работы. Ошибки/повторы не удваивают движение. |
| Удаление записи журнала | Запретить при любом связанном движении, сохранить историю | `PU_WORK_LOG_DELETE_POLICY=block_linked_writeoffs`; неизвестные значения отклоняются, физическое каскадное удаление расхода запрещено. |
| Выход на общем устройстве — заменено прямым заданием offline logout | Сохранить actor-scoped несинхронизированные команды, фото и операции; сразу закрыть сессию, очистить owned cache и приватный UI | Durable local fence, explicit login, scoped revoke-only queue. Прежний `VITE_OFFLINE_LOGOUT_PURGE` новый App logout не использует; автоматическое уничтожение unsent запрещено текущим заданием. |
| Точка чертежа | Явная immutable версия, страница с1 и относительные x/y в[0,1], начало в левом верхнем углу | `PU_DRAWING_POINT_POLICY=normalized_page_v1`; `disabled` отвергает новые точки. Без достоверной версии точку не принимать. Ориентацию/реальное попадание проверить на образце. |

Конфигурация читается по именам из явно заданного окружения либо передаётся вызывающим кодом; `.env` не читать. Неизвестная политика — ошибка, не тихое переключение. Изменение настройки не переписывает историю, цены старых КС, архивы и версии чертежей.

Синтетические КС/ИД явно помечаются как SYNTHETIC/«СИНТЕТИЧЕСКИЙ ОБРАЗЕЦ — НЕ ДЛЯ ПОДПИСАНИЯ». Образцы не объявляются официально утверждёнными формами заказчика. 1С/Диадок — только локальные интерфейсы и mock, реальные endpoint/schema/auth не придумываются.

Точки чертежа сейчас являются проверенной scoped metadata-привязкой к версии: реальные границы/ориентация PDF и попадание в элемент проверяются по образцу; автоматический перенос на другую версию запрещён. Это не подтверждение отрисовки или существования указанной страницы в реальном файле.


## Физический склад: исторические единицы и повтор — 04.11.2026

**Предварительное решение, требует подтверждения:** при несовпадении единицы новых движений с историей блокировать запись, автоматическую конверсию не выполнять. Смешанная старая история остаётся доступна, численный остаток не показывается. Истинный повтор и сторно сохраняют исходную единицу. Складские POST сохраняют actor/project intent до отправки; удаление локального повтора не отменяет серверную запись и требует подтверждения. Настройка отрицательного остатка PU_NEGATIVE_STOCK_POLICY остаётся отдельной; она не разрешает смешение единиц.


## Offline фото — технический бюджет 04.11.2026

Предварительное решение, требует подтверждения: хранить исходники без сжатия, максимум12 файлов по10MiB и20MiB на замечание; отказ квоты сохраняет форму. Новый фото-create всегда сначала пишет единый IDB intent, отправка считается законченной только после всех typed квитанций. После удаления фото tombstone запрещает позднее восстановление повтором. Это не приёмка реальной камеры/телефона.


## Предварительный API grant и renderer budgets — 04.11.2026

**Предварительное решение, требует подтверждения:** будущий API grant — readonly document.read ровно для одного tenant/project/principal, explicit expiry/revoke и server membership. Пока только queued policy contract, не работающая выдача настоящих ключей. Renderer — только synthetic/private tmp,10MiB input/1600px/16MiB PNG/10s/512MiB/8CPU seconds как технические budgets; implementation/native checks UNRUN, зависимости стенда не готовы. Ни один из этих пунктов не активирует production.

## Offline logout — прямое уточнение 05.11.2026

Сохранность неотправленных фото и правок задана пользователем явно, поэтому прежний предварительный destructive default заменён этой строкой таблицы. До выхода — подтверждение с предупреждением; отмена не меняет сессию или данные. Сохранённые очереди доступны только прежнему actor после явного подтверждённого входа. Несохранённые поля формы требуется сохранить до подтверждения выхода. Подробные допущения HttpOnly/HTTP cache — NOTES.md. Старые helpers `frontend/src/offline/logoutPolicy.ts` оставлены для совместимости, но новый App logout их не вызывает; не возвращать автоматический purge очередей.
